## Scope and result

Reviewed the Web SDK transport, configuration, identity/storage, event queues, ads, sponsorships, referrals, attribution, feedback, React hooks/components, package outputs, documentation, and existing tests. Compared requests with the adjacent GrowthCatBackend source, including routes, schemas, identity middleware, reward validation, and bootstrap configuration.

The SDK is not ready for a production reliability/security sign-off. The main routes exist, but several advertised integrations fail against the local backend contract. Findings below distinguish currently exercised legacy behavior from failures that appear when v2 is enabled.

Backend evidence is from the local checkout, whose backend/ and docs/ directories are untracked. This is not verification of the deployed API. No production traffic, reward grants, or backend mutations were performed. Application source was not changed during this review.

## Release blockers

### 1. [P1] Reward validation accepts zero viewing time

Backend `backend/src/modules/ads/ads.service.ts:3604` sets `requiredSeconds = 0`, making `completed: false, viewed_seconds: 0` pass. The route at `backend/src/modules/ads/ads.route.ts:166` requires only the public SDK key. The response always says `reward_validated: true`, even though the reward name/amount are null; it does not condition success on `accepted`. The SDK trusts this in `src/react/components/GrowthCatAdInterstitial.tsx:261` and creates a fresh event ID for every validation in `src/services/ad-service.ts:172`.

An integrating app that grants an entitlement on `onReward` can be induced to grant without satisfying the viewing requirement. Campaign ownership checks in event ingestion do not establish viewing. Fix on the server: validate the rewarded placement policy, bind validation to a server-issued delivery token and verified user, and make redemption idempotent per delivery. Client timing alone cannot authorize valuable rewards.

### 2. [P1] Attribution and reward lookup cannot supply required identity authentication

`src/core/api.ts:435` only sends the SDK key and workspace headers. The backend requires `X-GrowthCat-Identity` on share-link, resolve, claim, events, rewards, and rewards/progress (`backend/src/modules/attribution/attribution.route.ts:130`, `backend/src/middleware/requireSdkIdentity.ts:3`). Missing tokens yield `401 verified_sdk_identity_required`.

Add an asynchronous host-provided token supplier, including user-scoped tokens and event-scoped tokens bound to event name and stable event ID. Tokens must be minted by the integrating app's trusted server; never ship the signing secret in the browser. Include refresh/retry behavior and user-switch handling. The local diagnostic confirms the missing header.

### 3. [P1] Documented funnel properties cause permanent event loss

`src/services/analytics-event-tracker.ts:12` permits `offering_id`, `placement`, `package_id`, `reason`, and `store`. The backend's strict properties schema at `backend/src/modules/analytics/analytics.schema.ts:34` rejects these fields. Conversely, backend-supported `has_intro_offer` and `purchase_result` are removed by the SDK.

Consequently, normal documented checkout/paywall payloads receive 400, and `AnalyticsEventTracker.flush()` permanently removes them. Reproduced all four affected funnel event types against the actual backend Zod schema. Agree on one versioned property contract, test actual serialized requests against it, and expose permanent ingestion failures to hosts.

### 4. [P1] v2 capability negotiation and event payloads do not agree

Backend `backend/src/modules/validate/validate.controller.ts:52` does not advertise `measurement_schema_version`. `src/models/bootstrap.ts:77` defaults to v1, so `src/core/api.ts:165` strips creative instance, measurement mode, SDK version, and country from ad events; sponsor batches become legacy slot-only calls at `src/core/api.ts:347`. This loses the booking/render association and deduplication data needed for reliable sponsored delivery reporting. Partial success in the legacy Promise.all path also causes successful requests to be retried with the rest of the batch.

Simply advertising v2 is insufficient: ad events always include `session_id` in essential mode (`src/services/ad-event-tracker.ts:138`), which the backend rejects. Sponsor events omit per-event `schema_version: 2` (`src/services/sponsor-event-tracker.ts:61`), required even inside a v2 batch, and also include session IDs in essential mode. Both schema failures were reproduced. Coordinate capability advertisement with corrected payloads and end-to-end contract tests.

### 5. [P1] Disabled measurement can still transmit queued or direct events

`src/client.ts:424` sends an uncached sponsor event directly without checking measurement mode. Analytics and ad trackers restore persisted events before applying initial privacy state; their `flush()` methods do not check current consent (`src/services/analytics-event-tracker.ts:50`, `src/services/ad-event-tracker.ts:153`). The ad timer and online listeners can therefore send old optional events after restarting with essential/disabled measurement. Moving essential to disabled also leaves existing essential ad events queued. Sponsor analytics events survive analytics-to-essential transitions.

Reproduced the uncached sponsor bypass and persisted optional replay under disabled mode. Enforce policy on initial restoration, enqueue, and every send; clear disallowed pending events and stop retries on revocation. Keep legitimate explicit referral/reward operations separate from optional analytics, with a documented policy for arbitrary `track()` events, currently allowed in essential mode.

### 6. [P1] CommonJS core and React exports hold different singleton clients

The build command in `package.json` bundles both CommonJS entry points independently. `dist/index.js` and `dist/react/index.js` each contain their own `_client`. Initializing the core CommonJS package does not initialize the client used by React hooks. Reproduced with the built package and react-test-renderer: `useAd()` returns `not_initialized` after core initialization and readiness.

Emit a shared CommonJS core or externalize the core dependency from the React entry. Replace the existing export-existence smoke test with an integration test that initializes the core and exercises a hook for both module formats.

## Reliability and measurement findings

### 7. [P2] In-flight completion removes an unrelated analytics event

`src/services/analytics-event-tracker.ts:72` acknowledges with `queue.shift()`. If consent clears the queue and a new event is enqueued before the old request finishes, its completion removes the new event. Queue-cap eviction can cause the same problem. Reproduced: send A, revoke/re-enable, enqueue B, resolve A; B is never sent. Remove by immutable event ID and protect against stale queue generations.

### 8. [P2] Shutdown does not stop ongoing queue drains or newly scheduled retries

Shutdown clears existing timers/listeners but no tracker records a stopped state. In-flight completions schedule microtasks or new retry timers afterward (`src/services/analytics-event-tracker.ts:75`, `src/services/ad-event-tracker.ts:167`, `src/services/sponsor-event-tracker.ts:95`). Reproduced a second analytics HTTP request after shutdown. This also matters when initialize replaces a client. Add lifecycle guards, request cancellation where appropriate, and tests for success/failure arriving after shutdown.

### 9. [P2] Sponsor group visibility is treated as visibility of every creative

`src/react/components/GrowthCatSponsorBanner.tsx:44` observes the whole multi-sponsor grid. `src/react/hooks/useSponsor.ts:73` records an impression for every child when that group is 50% visible. In a grid extending below the viewport, completely invisible sponsor tiles receive impressions. Observe each rendered creative independently and pass its own duration/fraction to tracking.

### 10. [P2] Referral initialization examples omit a required user identity

`src/client.ts:159` allows `/validate` without an app user ID; `backend/src/modules/validate/validate.schema.ts:4` requires one. The built-in referral examples only initialize the SDK and therefore fail for a fresh anonymous installation. Reproduced the schema rejection. Validate the identity requirement locally with `missing_app_user_id`, and update the integration documentation. The form also ignores `showCodeRedeemUI`; the server execution flag is checked, but the hidden-UI configuration is not respected by the built-in UI.

### 11. [P2] Referral funnel sessions are not connected by default

Referral clicks and validation send only caller-provided session IDs (`src/client.ts:161`, `src/client.ts:184`), while paywall/checkout events default to an internal measurement session. Anonymous clicks cannot be joined to subsequent funnel activity through that session unless the host manually supplies consistent context. Use a consistent session policy across entry points. Referral clicks also bypass the durable queue and have no stable deduplication ID, so transient failures undercount the top of the funnel.

### 12. [P2] Attribution retry persistence is incomplete

`src/services/attribution-service.ts:159` enqueues the first failed event without scheduling a retry. Storage failure discards it entirely despite the in-memory fallback comment. Queue draining writes a local snapshot after awaits, so an overlapping enqueue or sign-out can be overwritten (`src/services/attribution-service.ts:173`). Requests lack original event time/session and stable event identity. After identity support is added, preserve an event-scoped token/ID across ambiguous retries so reward-triggering events cannot be counted twice. Also align event-name limits: SDK 128 characters, backend 120.

### 13. [P2] SDK geographic data can misclassify audience and targeting

`src/services/ad-service.ts:27`, `src/services/ad-event-tracker.ts:32`, and `src/client.ts:568` derive country from `navigator.language`. An `en-US` browser in Madrid is reported as US, and that inferred region is sent as an ad-selection country override. Use locale solely as language/locale; use trusted server geolocation or an explicitly documented host-provided country for targeting and geographic reports. Do not interpret numeric language regions such as `419` as two-letter country codes.

### 14. [P2] Feedback board pagination and filtering do not match the API

`src/core/api.ts:369` returns only items, discards `pagination.next_cursor`, and exposes no cursor/limit input. The backend defaults to 50 items (`backend/src/modules/feedback/feedback.schema.ts:135`), leaving older items inaccessible from the SDK. The SDK sends `type`, but the backend public-items schema has no type field, so the built-in category filter does not filter the server result. Expose pagination and agree on a supported type filter, including a multi-page UI test.

### 15. [P2] Logs expose identifiers and response payloads

`src/core/api.ts:525` logs whole response bodies, and `publicUrl()` preserves query values. Debug logs can contain attribution tokens, feedback content, and reward user identifiers. Request-body key-only logging does not protect these response/query paths. Redact sensitive query values and use response summaries or an explicit safe-field allowlist.

### 16. [P2] SDK version metadata disagrees with the published package

`src/core/version.ts:1` is 0.0.5 while package.json is 0.0.6. The existing version-alignment test fails, and analytics diagnostics report the wrong installed version. Generate this constant from package metadata as part of the build/release workflow.

### 17. [P2] Development dependencies have published security advisories

The successful npm audit reports three affected package names: brace-expansion (high), js-yaml (high), and esbuild (low), with fixes available. These are development-tool dependencies, not direct browser runtime dependencies. Prioritize the high-severity parser/resource-exhaustion issues according to whether tooling processes untrusted input. The esbuild advisory concerns its development server on Windows; this SDK's tsup build is not evidence of that exploit path being exposed.

Sources returned by npm: [brace-expansion](https://github.com/advisories/GHSA-rgw5-rvv9-x895), [js-yaml](https://github.com/advisories/GHSA-5p4m-2wfm-xmqj), [esbuild](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr). Update affected development dependencies and re-run the build/test workflow; no dependency updates were made during the review.

## Further hardening

- Normal fetch requests have no keepalive/pagehide delivery strategy. Visibilitychange flushing does not guarantee delivery when leaving a page; attribution links and checkout navigation are important cases. Apply a bounded browser-compatible transport and keep durable retries with stable IDs.
- Use a client-owned identity/storage scope including workspace. Current mutable global scope is derived only from API key and base URL; multiple client instances and workspace changes can share or mix identity/queues. Add cross-tab queue coordination before claiming durable exactly-once behavior.
- Expire stale ad creatives/tokens rather than serving an indefinitely old cached ad after every network failure. Validate restored queue payloads and cap restored storage immediately.
- Validate response booleans strictly: `Boolean('false')` currently reports successful referral/reward flags. Treat malformed successful responses as typed protocol errors. Implement the advertised `app_setup_incomplete` error mapping instead of mapping all 409s to generic server errors.
- Accessibility needs integration coverage: referral inputs lack labels, icon buttons need names, dialog close should restore focus, and image/video readiness should be considered before declaring an impression. Sponsor qualification should reject non-finite visibility values.
- Optional analytics need an observable delivery API: enqueued/delivered/rejected state and an awaitable flush. Current async recording resolves before ingestion and drops rejected events silently when logging is off.
